# 로컬 AI 작업실 — 개발 이력과 운영 노하우

이 문서는 작업실을 만들면서 내린 결정, 겪은 문제와 해결법을 모은 것입니다. 서버를 옮기거나 기능을 고칠 때 같은 시행착오를 줄이기 위한 기록입니다.
(개발 PC: Windows 11, Intel Core Ultra X7 358H, 메모리 32GB, Intel Arc B390 내장 GPU / 2026-11)

## 1. 설계 원칙
- **외부 전송 없음**: 언어 모델(Ollama)·임베딩·이미지 생성 모두 로컬. 인터넷은 설치, 웹 검색, 위키백과 조사 때만 사용.
- **Docker·WSL 금지**: 네이티브 Python venv + Ollama. 서버판은 systemd(리눅스) / 작업 스케줄러(Windows) 로 상시 실행.
- **GPU에는 언어 모델 1개만**: 임베딩은 CPU, 이미지 모델은 쓸 때만 올리고 언어 모델과 번갈아 사용.
- **사용자는 명령어를 치지 않음**: 실행 파일·설치 스크립트 하나로 끝나야 함.
- **사실 검증 우선**: 모델 태그·라이선스·버전은 기억이 아니라 직접 조회. 확인 못 한 값은 "미확인"으로 표기.
- **결과물은 기관 형식**: HWPX(한컴), PPTX, XLSX, DOCX, PDF. 공공기관 개조식(□ ㅇ - ※) 문체 기본.

## 3. 모델 선택 경위
- 처음 사양은 Qwen2.5-14B. 비교 결과 **qwen3:14b**(속도 차이 0.6 tok/s 이내, 품질 우위) → 이후 **gemma4:26b**(MoE, 약 18GB, 그림을 볼 수 있음, 도구 호출 5/5 성공)로 교체.
- `think: false` 를 qwen3·gemma4·gpt-oss·deepseek-r1 에 항상 보냄 (추론 출력이 문체·속도를 해침).
- `num_ctx` 는 8192 로 **고정**. 호출마다 다르면 Ollama 가 모델을 매번 다시 올려 수십 초씩 지연됨.
- 개발 PC 실측: gemma4:26b 약 39 tok/s, 첫 반응 약 5초 (iGPU 가속 시).

## 4. 겪은 문제와 해결 (중요)
### 설치·실행
- **Ollama 가 CPU 100%로만 돎 (Intel Arc 내장 GPU)** → 환경변수 `OLLAMA_IGPU_ENABLE=1`, `OLLAMA_VULKAN=1` 필요. 사용자 환경변수로 영구 저장. 서버 설치 프로그램은 Intel GPU 만 있을 때 자동 설정.
- **winget·GitHub 다운로드 504** → ollama.com 직접 다운로드로 우회 (설치 프로그램도 두 곳을 차례로 시도).
- **실행 .bat 글자 깨짐** → 배치 파일은 ASCII + CRLF, 한글 이름은 감싸는 파일로 분리. `.cmd` 는 BOM 없이 저장(BOM 이 있으면 첫 줄 깨짐). PowerShell 5.1 용 `.ps1` 은 UTF-8 BOM 필수.
- **Streamlit 첫 실행 이메일 질문에서 멈춤** → `--server.headless true`.

### 문서 형식
- **HWPX 가 한글에서 빈 문서로 열림** → 직접 조립한 XML 대신 **한컴이 저장한 빈 문서(`assets/base.hwpx`)를 바탕으로** 글자·문단·테두리 모양을 복제·수정.
- **표가 쪽을 못 넘김** → `treatAsChar=0`. **제목만 쪽 끝에 홀로 남음** → `keepWithNext`.
- **PDF 에 ₩Delta 같은 깨짐** → LaTeX 수식을 유니코드로 변환, 남은 역슬래시는 `/` 로 (맑은 고딕에서 `\` 가 ₩ 로 보임).
- **𝜹 같은 수학용 글자** → NFKC 정규화.
- **.hwp 열기에서 무한 대기 (한컴 자동화)**:
  1) 창 숨김(`XHwpWindows.Item(0).Visible=False`) 호출이 `.hwp` 열기를 멈추게 함 → 쓰지 않음.
  2) 한 번도 허락하지 않은 폴더의 파일을 열면 **보이지 않는 보안 확인창**이 떠서 멈춤 → 시스템 TEMP 폴더에서 변환.
  3) 그래도 멈출 수 있으므로 **별도 프로세스 + 2분 제한**, 시간 초과 시 그 변환이 띄운 Hwp.exe 만 종료.
- **PDF 표의 칸이 섞임** (일정표 ● 가 몇 월 칸인지 모름 → AI 가 13~18월차를 19~24월차로 오답) → PyMuPDF `find_tables()` 로 표를 행 단위로 따로 뽑고,
  칸 안 줄바꿈('13 15 ~ 월차')도 숫자 순서로 복원. 검색 색인은 띄어쓰기를 지운 글자 n-그램(‘미래모빌 리티’도 찾힘).

### 모델 출력 품질
- **드문 음절 깨짐 ('듄' → 다른 글자)** → 고유명사를 자리표시자(TERMX)로 바꿔 생성 후 복원, 조사(은/는)도 받침에 맞게 재계산.
- **존재하지 않는 인물·출처를 지어냄** (웹페이지) → 위키백과에서 자료를 먼저 모으고, 자료에 근거가 없는 항목은 제거. 출처·제외 개수를 화면에 표시.
- **슬라이드 결과물이 엉망** → 자유 생성 대신 **JSON 구조(제목·KEY POINT·bullets·표·출처·아이콘)** 를 받아 파이썬이 디자인 시스템대로 그림.
- **사용자 의도를 못 알아들음** ("그림과 표를 추출해서…"를 요약으로 처리) → 요청 문장으로 작업 종류 자동 판단.
- **간트 기간 오류** → LLM 에 맡기지 않고 일정표(●·■)를 파이썬이 직접 계산(머리글 '1~3월차', 'M1', '1분기', '1차년도', '2026.04', '4월' 인식) 후 LLM 결과에 덮어씀.
  문서에 기간이 없으면 상위 기간을 물려받되 **'추정'으로 빨간 표시**. 근거 구절이 원문에 있는지 대조해 '확인 필요' 표시.

### 디자인
- **SVG 로고가 검게 나옴 (PyMuPDF)** → 그라디언트·클리핑이 있는 SVG 는 Edge 헤드리스로 PNG 변환 (`slide_themes/rasterize_logos.py`). 단순 선형 아이콘은 PyMuPDF 로 충분.
- PPTX 표 테두리는 스키마 순서(lnL, lnR, lnT, lnB → 채우기)대로 넣어야 PowerPoint 복구 경고가 안 뜸. 표 스타일은 "No Style, No Grid".
- 글꼴은 레거시 패밀리 이름(`Gmarket Sans TTF Bold`, `KoPubDotum Medium`)으로 지정하고 동아시아(ea) 글꼴도 함께 설정.
- 긴 표지 제목은 쉼표 뒤에서 줄을 나누고, 줄 길이에 맞춰 글자 크기를 자동으로 줄임.

### 이미지 생성 (ComfyUI)
- 32GB 메모리에서 gemma4:26b(약 20GB)와 이미지 모델은 **동시 상주 불가** → 생성 전 LLM 내림, 다른 메뉴로 가면 이미지 모델 내림.
- 가중치 FP8(`fp8_e4m3fn`)이 기본 (메모리 절약, 품질 차이 미미).
- **DEVICE_LOST(GPU 장치 손실)로 멈춤** → 로그 감시로 감지 → ComfyUI 재시작 후 1회 재시도, 전체 900초 제한.
- 같은 시드·설정이면 ComfyUI 가 캐시 결과를 돌려줌 → 시험 때는 시드를 바꿀 것.
- 참조 이미지 편집: VAEEncode → ReferenceLatent 를 긍정·(0으로 만든) 부정 조건 양쪽에 연결 (FLUX.2 Klein).
- 인물 사진은 본인 또는 동의받은 사진만 (화면 안내).

### 마인드맵
- 그리기는 외부 라이브러리 없이 직접 배치(가지 무게로 좌우 균형) → SVG·PIL·PowerPoint 도형이 같은 좌표를 씀. PPTX는 그림이 아니라 둥근 사각형 + 곡선 연결선이라 받은 뒤 고칠 수 있음.
- 노드가 30개를 넘으면 '전체 구조' 장은 2단계까지만 그림(글자가 읽히게), 세부는 가지별 장에.
- KEY POINT 띠는 약 44자까지 → AI에 38자 이내 headline 을 따로 요청하고 넘치면 띄어쓰기 기준으로 줄임.
- 긴 문서는 제목·개조식 줄 위주로 압축(skeleton)해서 8K 문맥 안에 넣음.

### 지식보관함 검색·속도 (2026-11-17)
- **임베딩 검색만으로는 문서 번호·수치·고유명사를 놓침** (MiniLM 은 'XK-9981', 'num_ctx' 같은 글자를 뜻으로 못 잡음) → 글자 n-그램 TF-IDF 순위와 RRF(1/(60+순위))로 합침.
  새 모델을 받지 않으므로 설치 패키지는 그대로. 소규모 시험(질문 12개)에서 정답 조각 포함 4 → 9.
- **임베딩 유사도는 관련성 판정에 못 씀**: "점심 메뉴 추천"에 짧은 조각이 0.76 으로 나옴 → 질문 낱말의 두 글자 묶음이 조각에 나오는 비율(coverage)로 느슨하게 1차 거르고,
  최종 판단은 답변 프롬프트에 맡김("관련 없으면 자료를 무시하고 번호를 달지 말 것"). 인용 번호가 없으면 출처 상자를 띄우지 않음.
- **폴더 연결은 복사하지 않고 증분 색인**: (수정 시각, 크기)가 같으면 건너뜀. 읽기 실패한 파일도 기록해 매번 재시도하지 않음(파일이 바뀌면 다시 시도).
  드라이브가 잠시 끊겨 폴더가 안 보이면 그 폴더 문서는 **지우지 않음**. 구글 문서(.gdoc)는 PC에 내용이 없는 바로가기라 읽을 수 없어 건수만 알림.
- **LLM 결과 재사용은 '같은 입력이면 같은 답이어야 하는' 단계에만**: Map 조각 요약·중간 병합·간트 추출. 최종 문서 작성(Reduce, 보고서)은 재사용하지 않음
  — 사용자가 다시 만들기를 눌렀을 때 다른 결과를 기대하기 때문. 열쇠 = 모델 + 메시지 + 옵션 해시, 30일·3,000개 한도, 위치 `outputs/.cache`.
- 파일 변환 결과(PDF 표 인식, .hwp 한컴 변환)는 내용 해시로 디스크에 보관. 형식이 바뀌면 캐시 종류 이름(`pdf2`)을 올릴 것.
- 병렬 처리(`OLLAMA_NUM_PARALLEL=2`)는 적용하지 않음: 26B 모델 + 문맥 2배는 32GB 공유 메모리에서 여유가 없고, 실측하지 않았음(미확인).

### 문서 비교
- 차이 찾기를 LLM 에 시키면 없는 차이를 만들거나 놓침 → difflib 로 결정적으로 찾고 LLM 은 요약만.
- 글자 단위 비교는 '12억→15억'을 '2→5'로 쪼갬 → 숫자·영문 낱말은 토큰 하나로 묶어 비교.
- 조문 모드는 조 번호로 짝을 맞춤. 번호가 밀린 개정은 조문마다 '수정'으로 나옴(화면에 안내). 부칙 등 같은 번호가 다시 나오면 '#2'로 구분.

## 5. 운영 팁
- 속도가 갑자기 느려지면: 사이드바 상태가 "일부 CPU 처리"인지 확인 → GPU 환경변수, 다른 프로그램의 GPU 메모리 점유 확인.
- 모델 교체: 사이드바 'AI 모델' 또는 `app/model.json`. 메모리가 부족하면 qwen3:14b.
- 결과물 백업: `app/outputs/history` (작업 보관함), `app/chroma_db` (지식보관함), `app/templates` (업로드 양식).
- 사용자 개인 사진·문서는 서버에 남으므로, 보관함 정리 주기를 정해 두는 것을 권장.
